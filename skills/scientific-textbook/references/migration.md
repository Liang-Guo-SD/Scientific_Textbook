# Migrate a Legacy Textbook Harness

Use this reference for older fixed-template, prose-only, Claude-oriented, or binary-status projects.

## Preserve before changing

1. Inspect repository state and preserve unrelated work.
2. Inventory chapters, appendices, harness files, scripts, datasets, artifacts, comments, and reviews.
3. Record the current authority order and identify contradictions.
4. Preserve historical decisions; supersede them with new entries rather than rewriting history.
5. Keep old chapters or prototypes until reusable content has reviewed destinations.

## Migration sequence

1. Create `CODEX.md` when only `CLAUDE.md` exists; retain the legacy file until active prompts and links are migrated.
2. Add `BOOK_ARCHITECTURE.md` and `QUALITY_GATES.md`.
3. Convert the TOC from topic labels to primary learner capabilities and explicit statuses.
4. Build a prerequisite and coverage audit before renumbering, splitting, or deleting chapters.
5. Replace the universal eight-section rule with required learning functions while preserving a stable project-specific heading convention.
6. Replace the universal two-example rule with concept-to-evidence coverage. Retain running examples where they genuinely support transfer.
7. Add chapter contracts, structured registries, schemas, and validators in proportion to scale and risk.
8. Add profile-specific evidence, experiment, dataset, review, and release records.
9. Classify legacy chapters as canonical, needs-remediation, prototype, superseded, or source-only.
10. Validate links and status agreement before changing any item to complete.

## Compatibility principle

Do not rewrite a successful theoretical textbook into an engineering laboratory. Migrate the missing control surfaces—capabilities, prerequisites, evidence boundaries, quality gates, and state—while preserving the book's actual pedagogical identity.
